# Decisions

Format: date · decision · reason. Decisions that are hard to reverse are marked **(owner)**.

## 2026-11-16 – Phase 0

- **Mod-ID `astralvigil`, package `media.hofferbert.astralvigil`** (owner, given in the brief).
- **Repository public on GitHub** (`Migno/astral-vigil`) (owner, requested).
- **Build:** Gradle 9.9.1 (Kotlin DSL) + ModDevGradle 2.0.148 + Stonecutter 0.10. One codebase, two
  Stonecutter projects `1.21.1-neoforge` and `26.1-neoforge`. NeoForge only, no Architectury.
- **Active/VCS version is 26.1.** Newest API is the source of truth; 1.21.1 lives in Stonecutter
  comments. `ResourceLocation`→`Identifier` handled by a Stonecutter string replacement.
- **Versions** (verified 2026-11-16): NeoForge 21.1.266 / 26.1.2.126, Parchment 1.21.1-2024.11.17,
  GeckoLib 4.9.3 / 5.5.2, BlockPilot 1.3.1.
- **BlockPilot is not on Modrinth** – it ships as GitHub release assets. Resolved through an Ivy
  pattern repository (`dev.blockpilot:blockpilot:<ver>:<mc>-neoforge`), `localRuntime` only, so it
  never ends up in the release jar or POM.
- **Compat instance:** compat mods are a separate non-transitive `compatMods` configuration copied into
  `run/<target>/compat/mods` (`prepareCompatMods`) – production jars work in dev because NeoForge
  runs Mojang names at runtime on both targets. 26.1.2 has no EMI build → JEI there, EMI on 1.21.1.
  Embeddium/Oculus are not needed: Sodium and Iris have official NeoForge builds for both targets.
- **GameTests:** version-neutral catalogue (`AVGameTests.ALL`) + version-specific registration
  (`@GameTestGenerator` on 1.21.1, `TEST_FUNCTION` registry + `RegisterGameTestsEvent` on 26.1).
- **Generated resources are committed** per target (`versions/<target>/src/generated/resources`),
  because data formats differ between 1.21.1 and 26.1 and CI should not need a datagen client.
- **Spotless without a code formatter.** palantir-/google-java-format rewrite `//?` Stonecutter comments
  to `// ?` and sort imports out of version conditionals, which breaks the inactive target. Spotless only
  enforces whitespace hygiene; style comes from `.editorconfig`. It lives on the root project (Stonecutter
  warns that root becomes "buildable" through the `base` plugin – harmless; `spotlessCheck` runs in CI).
- **Project path contains a space** (`D:\dev\minecraft\Astral Vigil`). Gradle/MDG handle it; all
  scripts quote paths. If a tool breaks on it, move to a path without spaces.
- **Windows Defender:** excluding the project folder and `%USERPROFILE%\.gradle` speeds up builds a
  lot. Not applied automatically – owner can run (admin PowerShell):
  `Add-MpPreference -ExclusionPath "D:\dev\minecraft\Astral Vigil","$env:USERPROFILE\.gradle"`

## 2026-11-16 – Phase 1

- **Starfall without an entity.** The falling star is a server-tracked animation (position lerp + particle packets)
  instead of a custom entity. Avoids a version-specific entity renderer (26.1 render-state pipeline vs 1.21.1) and
  save/load edge cases; a star in flight is simply dropped on server stop. Custom client-side particles follow in
  Phase 5.
- **Recent impacts are kept in memory** (16 per dimension) for the Astrolabe – not persisted, they are a hint, not
  progression state.
- **Translations live in one table** (`datagen/AVLang`) with English and German side by side, so a key cannot exist in
  only one language; the JUnit test additionally checks the generated files and placeholder counts.
- **Tooltips via `ItemTooltipEvent`** instead of `appendHoverText` (signature differs between targets).
- **GameTest positions via `GT.pos()`**: 1.21.1 puts relative y=0 at the structure block, 26.1 at the structure origin.
- **Datagen classes are client-only** (26.1 model providers live in `net.minecraft.client.data`), registered from the
  client entry point so a dedicated server never loads them.
- Textures: three extra in-between shades were allowed (deep crystal blue `#1C5C8A`, rock mid `#2C2942`, rock light
  `#3D3959`); every texture stays at ≤ 8 colours.

## 2026-11-17 – Phase 2

- **Alignments are tags, not code.** Four tag families per alignment (block, entity type, biome, structure) so
  packmakers can re-align anything with a datapack. `Alignment` itself is a pure enum (unit-testable); the tag keys
  live in `AlignmentTags`.
- **Research is a player attachment** (`astralvigil:research`): immutable record, MapCodec persistence, StreamCodec
  sync to the owner only. Players without a negotiated channel (GameTest mock players) are skipped.
- **Unlocks via advancements.** Research milestones are advancements with an impossible criterion granted from code.
  This gives toasts, the vanilla advancement tree and Patchouli entry locking for free.
- **Patchouli is optional and reflection-only.** No compile dependency (API package/IDs differ between targets); the
  book JSON is generated by `AVCodexProvider` from `CodexContent` (en + de), so no hand-written JSON.
- **Star Chart screen without textures.** Drawn with `fill`/text only behind a tiny `Canvas` adapter – the GUI API
  changed completely in 26.1 (`GuiGraphicsExtractor`, `MouseButtonEvent`), the adapter keeps game logic shared.
- **Constellations are code-defined for now** (four, one per Watcher). Data-driven constellations can follow if
  packmakers ask; Phase 6 Star Anchors consume the learned set.
- **Compat mods pinned by Modrinth version id.** Resolving by version number picked Fabric jars (JEI, Patchouli).

## 2026-11-17 – Phase 3

- **Push-based network, once per second.** Every device re-traces its beams (≤ `beamRange` lookups) and pushes into
  the device it hits every 20 ticks. Simpler and more robust than a cached graph with block-change listeners (vanilla
  block changes fire no events), still O(devices × range) per second and nothing per tick. Clients only get a block
  update when beams or amounts change.
- **Tinted buffers.** Starlight carries a tint (pure, Sol, Luna, Stella); all tints share one capacity. Void light is
  reserved for the Eclipse.
- **One device block class** (`StarlightDeviceBlock` + `Kind`) instead of five classes; codecs per kind.
- **Beam visuals reuse the vanilla beacon beam helper** (rotated onto the axis, thinner, tinted) – looks vanilla,
  works on both renderers (26.1 submit/render-state pipeline and 1.21.1 immediate mode).
- **Jade data is client-side only** (synced block entity), so no server data provider is needed.
- **Datagen and builds:** `runData` must run in its own Gradle invocation; a `mustRunAfter` would create a task cycle
  (runData needs `classes`).
- **Blockbench assets without plugin file access.** Models are read back via `execute_script`
  (`Codecs.java_block.compile()`) and written by script; the owner answered Blockbench's file-permission prompt.

## 2026-11-17 – Phase 4

- **Real recipe types** (`StarlightRecipe`, one record for both types) instead of a custom JSON format: works with
  datapacks, `/reload`, KubeJS `event.custom`, recipe viewers. All inputs are `Ingredient`s – the shipped recipes use
  tags only. On 26.1 the result is an `ItemStackTemplate` (ItemStacks cannot be built during datagen), on 1.21.1 an
  `ItemStack`; 26.1 clients get the recipes via `OnDatapackSyncEvent#sendRecipes` + `RecipesReceivedEvent`.
- **Altar and forge are starlight receivers**, not reservoir-scanners: light arrives by beam or from a touching
  reservoir, so the Phase 3 network stays the single source of energy.
- **Stability is recomputed every second** during a ritual (cheap: ≤ 9×3×9 + 7×4×7 lookups) – players can fix a ritual
  while it runs.
- **In-world items instead of GUIs** for pedestal/altar/forge (no menus, no cross-version screen code); items float
  via a block entity renderer.
- **Empty-hand actions require an empty main hand** – otherwise the off-hand pass after inserting an item would take it
  straight back out.
- **EMI only on 1.21.1** (no 26.1 build exists yet); JEI on both. Compat ids pinned in `stonecutter.properties.toml`.

## 2026-11-17 – Phase 5

- **Wing cosmetic moved to Phase 7.** The brief wants GeckoLib only for the wings; GeckoLib 4 (1.21.1) and 5 (26.1)
  have different packages and render APIs, and Phase 7 needs the same GeckoLib layer for the Watchers anyway. Doing it
  once there avoids two half-integrations.
- **Gear state is one data component** (`astralvigil:gear`: deeds, sigils, stance, charge, cooldown) – survives
  anvils/repairs, shows in tooltips without extra sync.
- **Abilities via key binds (V/B) + C2S payload**, executed and validated server-side (charge, cooldown, stance).
- **Socketing via `PlayerInteractEvent.RightClickItem`** (sneak + sigil in off hand) instead of overriding `use` in
  six vanilla item subclasses with version-specific signatures.
- **Arrow bonuses via entity tags + `LivingIncomingDamageEvent`**: 26.1 removed `AbstractArrow#getBaseDamage`, so
  arrows are tagged at creation (`customArrow`) and scaled on impact – identical on both targets.
- **Starlight Aegis uses a flat item model** (no block-entity-without-level renderer): blocking works on both targets
  (1.21.1 `ShieldItem`, 26.1 `BLOCKS_ATTACKS` component), and the art stays vanilla-style pixel art.
- **GameTests drive starlight devices explicitly** (`helper.onEachTick`): GameTest chunks are not always
  block-ticking on 1.21.1, which made beam/forge tests flaky.
- **Gear recipes upgrade vanilla gear** at the Convergence Altar (diamond sword → Halo Edge …): keeps enchanting
  progression meaningful and makes recipes easy to override with KubeJS.

## 2026-11-17 – Phase 6

- **Structures from generated templates.** The observatory NBT is produced by `tools/dev/gen_observatory.py`
  (deterministic, versioned) rather than hand-built in a world; worldgen JSON comes from datagen
  (`AVWorldgen` registry bootstrap). Packs disable it by overriding the structure set.
- **Four template variants** (one per constellation lock) in one pool instead of a randomising processor – simple and
  identical on both targets.
- **Lore unlocks via advancements without display** – the Codex locks each Chronicle page on `lore/fragment_N`.
- **Gaze lives in a player attachment** (synced to its owner). It only falls through rituals, as the brief asks;
  every effect has a config switch (`crystallizeBlocks`, `enabled`).
- **Eclipse Echoes are named, short-lived Vexes** until the Eclipse creatures exist (Phase 7/8).
- `/locate structure` is very slow in this dev setup even for vanilla villages; structure generation was verified with
  `/place structure` and GameTests instead.

## 2026-11-17 – Phase 7

- **GeckoLib is a hard dependency** (4.9.3 / 5.5.2), pinned by Modrinth version id and declared `required` in
  `neoforge.mods.toml`. The 4.x→5.x root package move is a Stonecutter string replacement
  (`software.bernie.geckolib` ↔ `com.geckolib`); remaining API differences (controller constructor, AnimatableManager
  package) sit in `//?` blocks.
- **One shared Watcher rig** (`watcher.geo.json` + `watcher.animation.json`, assets in both GeckoLib layouts:
  `geo/`+`animations/` for 4.x, `geckolib/models|animations/` for 5.x) and one entity type per Watcher with its own
  texture via `DefaultedEntityGeoModel#withAltTexture`. GeckoLib 5 resolves textures from the render state, so one
  model instance per entity type is the simplest cross-version solution.
- **Firmament = vanilla floating-islands noise + overworld dimension type** (datagen `LEVEL_STEM`), identical on both
  targets. The sanctum hub is built once at y 290 – above the island terrain – from generated templates
  (`tools/dev/gen_firmament.py`); the unbreakable Starlight Font at the landing marks "already built".
- **Experimental-settings warning:** every datapack dimension makes vanilla flag the world as experimental. NeoForge
  remembers the confirmation per world (`confirmedExperimentalSettings`), so players see it once – same as all
  dimension mods; no mixin.
- **Low gravity via transient attribute modifiers** (`gravity` −50 %, `safe_fall_distance` +7) applied while in the
  dimension; falling below y −32 returns you to the landing.
- **Trials are short, server-side and stateless in the world:** the active trial is two keys in persistent player
  data (10 min timeout); completion is an advancement (`firmament/trial_<watcher>`) + Mark item + favour. Favour is a
  synced player attachment (copy on death). Rivals: Solenne ↔ Vael, Orrin ↔ Ilyra.
- **Seraph wing cosmetic moved to Phase 8:** it needs a GeckoLib player render layer, which Phase 8 builds anyway for
  the Eclipse; doing it once keeps the version-specific layer code in one place.

## 2026-11-17 – Phase 8

- **Eclipse phases are derived from health** (> ⅔, > ⅓, rest) – nothing to persist, survives reloads; each phase
  change is a 2.5 s invulnerable transition with a short shockwave.
- **Readable attacks over raw stats:** telegraphed Void Lance (wind-up, dodge sideways), Echo waves (max 6 alive),
  Umbral Nova that cover blocks. Damage values are config options.
- **Summoning:** Umbral Sigil (Convergence Altar), only in the Firmament, only with all four Marks, never on Peaceful
  (the sigil would be wasted). Marks are kept, so the fight is repeatable for more feathers / hearts.
- **Boss loot in code** (Eclipse Heart + 3–5 Seraph Feathers, counts in config), like the Wither's Nether Star; the
  kill advancement is granted to every player within 48 blocks so groups all get credit.
- **Low gravity + knockback threw players off the islands**, so the sky beneath the hub now catches you: falling more
  than 24 blocks below the landing within 160 blocks of it returns you to the landing with Slow Falling. Islands
  further out stay explorable; knockback values were reduced too.
- **Seraph Wings are a vanilla model layer, not GeckoLib.** The rig was authored in Blockbench and converted to a
  `LayerDefinition`; a vanilla layer works with every player renderer, skin-layer mod and shader pack, and needs no
  GeckoLib player hacks. Toggle via Seraph Feather (binding consumes one), state is a player attachment synced to all
  tracking clients.
- **Eclipse Echoes** replace the Phase 6 Vex placeholder (GeckoLib, 30 s life when summoned by Gaze).
- **Halo of Dawn** is utility, not damage: −25 % ability cost, −50 % Gaze gain while carried (config).
- No spawn eggs: 26.1 spawn eggs need the entity type at item registration time (registered after items) and their
  own textures; `/summon` covers testing.

## 2026-11-17 – Phase 9

- **Profiling result is the baseline:** the starlight network costs ≈ 0.06 ms/tick for 96 devices; reservoirs sync
  their fill once per second, which is the largest packet source (1 BE update/s per changed reservoir) and is kept –
  the client needs it for the fill display and Jade.
- **ATM smoke tests are blocked on the server packs** (`tools/atm-smoketest.ps1` is ready); the dev compat instances
  (Sodium, Iris, JEI/EMI, Jade, Patchouli, Curios, Apotheosis, KubeJS) ran clean on both targets.
- **Publishing:** drafts only (`docs/publishing/`); slug, license and release channel are owner decisions.

## 2026-11-17 – Developer cosmetics

- **Server decides access**, never the client: built-in `CosmeticsManager.TEAM` UUID set (empty until the owner adds
  their Mojang account UUID), the `[cosmetics] developers` server config list, and every player in a development
  environment. The decision is mirrored to the client (`cosmetic_access` attachment) only to lock the screen.
- **Vanilla model layers, not GeckoLib**, like the Seraph Wings: they work with every player renderer and shader pack,
  and the emissive pass uses the vanilla `eyes` render type (GeckoLib emissives are broken on macOS/Linux).
- **Cape:** on 26.1 the vanilla `PlayerCapeModel` (exact cape physics) and `showCape=false` hides a Mojang cape; on
  1.21.1 the cape physics are copied from `CapeLayer` – a Mojang cape can overlap there (no mixin for it).
- **Textures and meshes are generated** (`tools/dev/gen_cosmetics.py`, pure Python, ≤ 8 colours checked); the
  generated `CosmeticMeshes.java` keeps box UVs and textures in sync.
- **Particles are client-only** and follow the particle-density setting; your own aura is hidden while the camera is
  in your head.
- `/astralvigil showcase <scene>` builds film-ready scenes for screenshots (op only).
- **Wardrobe key is J**, not K: Iris binds K to "toggle shaders" by default.
- **Iris "Missing sampler Sampler1" (Iris #3347) is dev-only:** vanilla 26.1 validates samplers only when
  `SharedConstants.IS_RUNNING_IN_IDE`; Iris' overridden item programs declare Sampler1 that vanilla item render types
  never bind, so only dev clients crash (any item, any mod set - reproduced with just Sodium + Iris). Normal installs
  never run that check. The compat run sets `-Dneoforge.disableGlValidation=true` to behave like a player install;
  verified with items in world and hand, all trial islands and rituals under Complementary Reimagined.

## 2026-11-17 – Watcher rework

- **Generated rig:** `tools/dev/gen_watcher.py` writes the geo, animations and all textures/glowmasks (≤ 8 colours
  checked) – it replaces `art/bbmodel/entity/watcher.bbmodel` as source of truth (the old 3-block rig was removed).
- **Glow:** vanilla `eyes` render type layer (GeckoLib 5 `TextureLayerGeoLayer`, GeckoLib 4 custom `GeoRenderLayer`),
  no GeckoLib emissive shader. Renderer scale 1.4, hitbox 1.8 × 5.6.

## 2026-11-17 – Built gate and large-scale Firmament

- **Gate uses the vanilla `Portal` interface** (transition time, cooldown, confusion overlay, portal ticket) – no
  custom teleport code. Shape detection is a pure flood fill (`GateShape`, JUnit-tested); any closed frame works.
- **Own dimension type** (overworld copy, y -64..447): the 26.1 and 1.21.1 records differ, so datagen runs vanilla's
  dimension-type bootstrap into a capturing context and copies the overworld entry (vanilla values are unbound in
  datagen). Worlds that visited the old Firmament keep their old islands; a fresh Firmament is built on first arrival.
- **Hard, not lethal:** the safety net returns fallers to the nearest island, Solenne's gold pads are checkpoints;
  difficulty comes from length, precision, archery under pressure and a dark maze.
- **The Eclipse is bound to the Umbral Throne** (summoned onto its dais) so the fight always has cover pillars.

## 2026-11-17 – One gate per challenge

- **Frame block decides the destination** (`GateKind`): one portal block per kind so the colour shows where it
  leads, and a gate frame must be a single kind. Same Ascension Key for all; the Umbral Gate additionally checks the
  four Marks when it is lit.
- **No bridges:** islands are only reachable through their gates; each has an arrival platform with a return gate
  and its Watcher. The first trip builds the whole Firmament (a few seconds, once).
- Vanilla's player portal cooldown (15 s after any dimension change) applies to every gate.

## Phase 10 – realms, masonry, Eclipse, armour (2026-11-17)

- **One dimension per gate, no hub.** The owner disliked the hub; each challenge lives in its own realm with a fixed
  atmosphere (26.1: fixed environment attributes and empty timelines; 1.21.1: fixed day time plus biome effects).
  Trial realms are void (flat generator without layers); the wilds keep vanilla floating-islands terrain with a carved
  hollow around the shrine. One template per realm; its anchor (128, 48, 128) is the arrival pad.
- **Floating blocks are vanilla block displays** driven through an access transformer: the server re-targets each
  pose every 40 ticks and clients interpolate. Smooth, cheap, shader-safe, no renderer code for two versions.
- **Trial realms are protected** (break/place cancelled, pearls fizzle, no elytra on the Sun Spire). This removes the
  pillar, pearl and dig cheese the audit found without special cases per trial.
- **Building blocks are data-driven** (`AVBuilding` entries plus vanilla `BlockFamily`), so datagen walks one list.
  Wood sounds and door/gate behaviour reuse the cherry set types.
- **Eclipse**: move state machine with synced move and stage, telegraphs drawn client-side; pylons are entities;
  phase-3 cover is vanilla crying obsidian tracked in the Eclipse's save data. 500 HP instead of 400 (shield phase).
- **Armour ornaments** use vanilla model parts with stateless animation and an `eyes` glow pass (works with the
  deferred 26.1 renderer and without GeckoLib emissives). Mid-tier sets are crafted at the Convergence Altar.
  `art/bbmodel/armor/seraph_layer_*` are stale; the assets now come from `gen_armor.py`.
- **Marks count by advancement** for the Umbral Gate and the summon, so a lost Mark cannot soft-lock the endgame.
